# robocode 0.6.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Battlefield ratios with urban maps, radar blocked by buildings, the blocked beam recorded and drawn, and a maneuver/risk library with a reference robot (Tactician) whose intent is recorded and shown.

**Architecture:** Ratios are presets over the existing `Battlefield`; each ratio's urban map is a literal table in `terrain.rs`. One line-of-sight function in `geometry.rs` is used by both the engine's scan rule and a new `physics::radar::radar_beam`, whose polygon the engine stores on each robot and the recording (v2) writes only when the arena has buildings. Maneuvers are a plain library in `strategy::maneuver` that returns `Action`s; `Tactician` composes them, and a new default `Strategy::intent` is carried through `StrategyRobot` into each frame's decision.

**Tech Stack:** Rust 2024 (MSRV 1.85), quickcheck 1.1, insta; wasm-bindgen crate in `wasm/`; clap CLI in `cli/`; React 18 + TypeScript + Vite + Vitest + three.js in `web/`.

**Spec:** `docs/superpowers/specs/2026-11-17-robocode-0.6.0-design.md`

## Global Constraints

- Battles stay deterministic: same robots, arena and seed give byte-identical recordings. No `rand`, no wall-clock time in maneuvers.
- An open-arena 800 × 600 battle between 0.5.0 robots gives a recording identical to 0.5.0's apart from `"version"`.
- `Observation`, `Action`, `TargetInfo` and `well_formed` do not change.
- No physics constants change (`src/rules.rs` untouched).
- Ratio sizes (equal height): 4:3 = 800 × 600, 2:1 = 1200 × 600, 16:9 = 1067 × 600, 1:1 = 600 × 600.
- Energy and power are thousandths (`Energy(u32)`, `Power(u32)`); angles are decidegrees (`Angle(i32)`, turns as `i32`).
- Recording format `roboverus-recording` version 2; viewers read 1 and 2.
- The 3D view does not draw the beam in 0.6.0 (documented in `docs/viewer.md`).
- Risk parameters ship with the spec's starting values; no tuning task.
- Commits: conventional prefixes (`feat:`, `test:`, `docs:`), no co-author/contributor trailers.
- Work on branch `v0.6.0` (from `fuzz-drift`).

## Review Focus

1. **Non-ratio sizes with `--urban`** (e.g. 1000 × 1000, 400 × 400) must still give 0.5.0's filtered map, not a ratio map or a panic → Task 2 keeps `every_arena_size_in_the_viewer_fits_its_urban_map` and adds `non_ratio_sizes_keep_the_0_5_0_filter`.

3. **A stationary radar in an urban battle** scans along a line; its beam must contain the scanned centre → Task 5 property generates `sweep = 0` cases explicitly.
4. **A robot that dies mid-battle** in an urban recording: its later frames must have `"beam":[]` and the viewer must not throw on an empty polygon → Task 6 `dead_robot_beam_is_empty`, Task 7 `draws_nothing_for_empty_beam`.
5. **`--ratio` together with `--arena`** must be a usage error, not a silent override → Task 3 `ratio_conflicts_with_arena`.

### Task 5: `radar_beam`

**Files:**
- Create: `src/physics/radar.rs` (add `pub mod radar;` to `src/physics/mod.rs`)
- Modify: `tests/properties.rs`
- Create: `tests/radar_beam.rs`

**Interfaces:**
- Consumes: `line_of_sight` (Task 4), `Rect::first_contact`, `rules::{ROBOT_RADIUS, RADAR_SCAN_RADIUS}`.
- Produces: `pub fn radar_beam(origin: Point, from_heading: f64, sweep: f64, buildings: &[Rect], field: &Battlefield) -> Vec<Point>`, a simple polygon in angle order around `origin` (counter-clockwise in screen coordinates is not required; consecutive vertices are what count). Headings use the engine's convention (0° up, clockwise, degrees); `sweep` is signed (`radar_heading - last_radar_heading`, normalized relative).

Algorithm (the tests don't pin it, so it is fixed here). Let R = `ROBOT_RADIUS` and S = `RADAR_SCAN_RADIUS`.
1. **Target region T:** the convex polygon that covers every point within R of the swept sector. It is the convex hull of:
   - (a) the square `origin ± (R, R)`;
   - (b) fan vertices at radius `(S + R) / cos(Δ/2)`, at angles evenly spaced from `lo − β` to `hi + β`. Here `[lo, hi]` is the sweep's heading interval, `β = asin(R / (S − R))`, and the step is `Δ ≤ 2°`.

   Clip T to the field rectangle with Sutherland–Hodgman. Because T is convex and contains `origin`, every ray from `origin` leaves it exactly once.
2. **Ray angles:** every vertex of the clipped T, and every building corner that lies strictly inside T. Cast each angle three times, at θ − ε, θ and θ + ε, with ε = 1e-5 rad. Sort the angles and remove duplicates.
3. **Ray length:** the distance to T's boundary along the ray, shortened to the nearest building contact. For each building, take `first_contact(origin, origin + dir·(S + 2R)·2)` and convert the fraction to a distance.
4. **Polygon:** the hit points in angle order. Merge runs of three or more collinear points (cross product < 1e-9 · length²) down to their two ends.

Behaviour (decidegrees and pixels):
- **search:**
  - `turn_radar = Some(450)`;

`choose` applies the spec's priority. A target is stale or missing when `target.is_none() || age > p.stale_after`. Below the reserve means `obs.energy < p.reserve`.

3. **Search** if the target is stale or missing.
4. **Defensive** if below the reserve.
5. **Attack** if the target is fresh (`age == 0`).
6. **Patrol** otherwise.

`decide`:
1. `shot = mem.observe(obs)`;
2. `next = choose(...)`;
3. if `next` differs from the current maneuver, reset `turns_in_maneuver` to 0;
4. `action = next.run(...)`;
5. increment `turns_in_maneuver`.
