## Global Constraints

- `robocode` keeps zero non-optional dependencies. A default build compiles no Verus crates, and `cargo build --features verus` works with plain cargo.
- Verus stays green for the crate and the solutions; the exercises fail only at their TODOs.
- Golden battles: `SafeShooter` vs Spinner = 386 turns, `77.0/-1.0`; vs SittingDuck = 364 turns, `147.0/0.0`. If a spec change alters behaviour, stop and record why.
- The recording fingerprint test stays unchanged.
- Commits carry no Claude attribution. Branch `verus-pdd`.

## Tasks

### Task 1: Mutation harness

- **Files:** `mutants/` (package `verus-mutants`, `publish = false`, a binary), `mutants/mutants.toml`-style manifest (a plain text format, no new dependencies), and the workspace member line.
- **Each mutant** has: an id, a file, an exact `find` string, a `replace` string, and `expect` (a substring of the targeted `ensures` clause, which must appear in Verus's failure output).
- **The runner:**
  - copies the crate, the solutions and the exercises into a temp dir, excluding `target/`, `web/` and `_wb/`, and shares a target dir;
  - checks that the unmutated baseline verifies;
  - then for each mutant it applies the edit, runs `cargo verus verify --features verus`, and requires both a failure and the `expect` text in the output.
  - It prints a table and exits 1 if any mutant survives, or if any `find` string doesn't match exactly once.
- **Start with one mutant per existing clause.** Record the survivors in the ledger: they are findings.

### Task 2: SafeShooter fires if and only if ready

- **The spec:** `ready(obs) = target fresh ∧ gun_heat == 0 ∧ aimed ∧ energy > 1000`. Add `ensures r.fire.is_some() <==> ready(*obs)`, and keep the safety clause.
- **The mutant "never fire"** survives Task 1. It must now be killed.

### Task 3: More contracts

- **`closest_target`:** if Task 1 shows `<` → `<=` survives, add the "first on ties" clause and invariant.
- **Movement:**
  - add `heading_into_near_wall` (spec) and give `toward_near_wall` the contract `r == heading_into_near_wall(..)`;
  - give `decide` this contract: moving forward means the heading doesn't point into a wall within `WALL_MARGIN`, and moving backward means the reverse heading doesn't.
  - Add a mutant for each new clause.

### Task 4: Trusted boundary and receipt

- **`Observation::is_well_formed()`** (exec, verified `ensures r == well_formed(*self)`). `well_formed` moves to `strategy` as a general spec. `StrategyRobot::run` checks it with `debug_assert!`, and a test runs full battles asserting every observation is well-formed.
- **`Angle::from_degrees`** becomes an `external_body` with `ensures 0 <= r.0 < 3600`, guarded by a test over extreme inputs (NaN, ±inf, ±1e300, −0.0).
- **`docs/verification-receipt.md`:** every requirement marked **proved** (spec and function), **tested** (the assumed clause and the test that guards it), or **out of scope**.
- **Pruning:** remove tests that only re-check proved `SafeShooter` behaviour, listing each one in the receipt with the clause that replaces it.

### Task 5: Guide chapter 4 and CI

- **`guide/src/ch04-spec-strength.md`**, mirroring the Verus guide's spec-strength advice. It covers vacuous specs, both readings and mutation checks. The exercise: strengthen a weak `clamp_power` spec until a client assertion verifies. Add the solution.
- **CI:** a `mutants` job in the Verus workflow runs `cargo run -p verus-mutants`.

### Task 6: Blog post

- **`docs/blog/2026-11-06-<slug>.md`**, in the style of the earlier post: what changed, what the mutants found, what is proved vs tested, and lessons. It cites the PDD Kit post.
